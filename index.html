Professional Self Assessment

Who I Am & What I've Built

My path through the Computer Science program at SNHU has given me exposure and practice with full stack development. I came into the program as a working DevOps Engineer with hands on experience in cloud infrastructure, container orchestration, and CI/CD pipeline design. However, without the formal computer science foundation that separates engineers who know how to operate systems from engineers who know how to design and evaluate them. The coursework closed that gap in measurable ways.

In data structures and algorithms, CS 260 gave me the analytical vocabulary to reason about time and space complexity, which I applied directly in this capstone by identifying and eliminating an O(n)+O(n) double query pattern in a database access layer and replacing it with a single indexed JOIN query. In software engineering, CS 360 and CS 320 gave me grounding in mobile architecture and software testing practices that informed the MVVM refactor I performed on this capstone's Android artifact. Moving from a monolithic 350 line Activity to a clean separation of ViewModel, stateless composables, and a UI state data class. In secure coding, CS 405 introduced the adversarial mindset that led me to identify plaintext password storage as the critical vulnerability it is and implement BCrypt hashing as the correct mitigation. In machine learning, CS 370's deep Q-learning and reinforcement learning coursework shifted my long term career target from DevOps systems engineering toward AI/ML engineering.

Collaborating in team environments has been a consistent thread across the program. In CS 250, working within an Agile Scrum simulation reinforced practices I use daily at my current workplace. Sprint planning, retrospectives, and the discipline of breaking large features into deliverable increments. Communicating with stakeholders, translating technical decisions into language that non-technical audiences can evaluate. These skills have been developed through the written narratives, code review, and professional self assessment work in this capstone. Security thinking runs through all three of my artifact enhancements. From defensive programming checklist items in the code review to the BCrypt implementation in the databases milestone.

The three enhancements in this portfolio tell a single coherent story about what it means to take a functional piece of software and make it production ready across three dimensions. The software design enhancement demonstrates architectural judgment, knowing when a working monolith needs to be broken apart and understanding the specific pattern (MVVM) that fits Android's component lifecycle. The algorithms enhancement demonstrates analytical thinking, recognizing an inefficient query pattern, reasoning about its complexity, and redesigning it with indexed JOIN queries that scale. The databases enhancement demonstrates security engineering, identifying a credential storage vulnerability, selecting the appropriate mitigation (BCrypt at cost factor 12), and migrating a legacy database layer to a modern, compiler validated ORM without breaking the layers above it. Taken together, they represent someone who works at the intersection of infrastructure depth and software quality, and who is building toward the AI/ML systems work that sits at that intersection's frontier.

Enhanced Artifacts

Three Enhancements, One Artifact

All three enhancements target the same Android inventory management application. A Kotlin and Jetpack Compose app built in a prior course, demonstrating growth across software design, algorithms, and databases using a single cohesive codebase.

Software Design & Engineering
Milestone Two

Refactored a 350 line monolithic Activity into MVVM architecture. Created InventoryViewModel with StateFlow, extracted all composables to a stateless InventoryScreen.kt, introduced InventoryUiState as a single coherent state snapshot, and reduced InventoryActivity to bootstrapping only. The ViewModel survives configuration changes automatically, eliminating data loss on screen rotation.

Algorithms & Data Structures
Milestone Three

Eliminated a double query pattern where every inventory read incurred two sequential database opens. Replaced with single JOIN queries that resolve username and fetch inventory in one pass. Added three explicit indexes on user_id, item_name, and category, reducing filtered queries from O(n) full table scans to O(log n) B tree traversals. Extracted shared cursor mapping helper and replaced magic number threshold with a named constant.

Course outcomes addressed: 3, 4

Databases
Milestone Four

Migrated the database layer from SQLiteOpenHelper to Room, replacing raw SQL strings with compiler validated @Query annotations and eliminating all manual cursor parsing. Defined UserEntity, InventoryItemEntity, UserDao, InventoryItemDao, and a repository layer that preserves the ViewModel's public API unchanged. Replaced plaintext password storage with BCrypt hashing at cost factor 12 eliminating the credential exposure vulnerability identified in the code review.

Course outcomes addressed: 4, 5
